# Y (the social feed) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fifth bottom-nav tab where the world talks about you — pundits, your own fans, rival fans and a stats account reacting to results, draws and tournaments — with public mood feeding the board.

**Architecture:** Two pure domain pieces (a public-mood model and a post generator), one provider that feeds the generator from events the world already records, and a screen. Posts carry a template id, a variant index and arguments rather than finished sentences, because the words are localised at render — the same shape the squad report already uses. Nothing is stored.

**Tech Stack:** Dart / Flutter, Riverpod (no codegen), `gen_l10n`.

## Global Constraints

- **Derived, never stored.** No tables, no columns, no schema bump. A post is a pure function of an event the world already recorded.
- **Deterministic.** The same event always produces the same posts — same author, same variant. Author and phrasing come from `varietySeed`/`pickVariant` in `lib/core/util/text_variety.dart`, seeded by the event's own key. Never `Random()`.
- **Neutral mood must contribute exactly zero to the board.** `BoardSatisfaction.compute` with `publicMood: 50` must return precisely what it returns with no mood at all. That is the guard that proves this feature did not silently re-tune the board.
- **Posts carry templates, not strings.** No sentence is assembled from fragments in the domain layer; Czech has seven cases and fragment assembly does not survive translation.
- **Every user-facing string in EN and CS**, through `flutter gen-l10n`.
- **Riverpod without codegen** — never add `@riverpod`.
- **Line length 80 characters.**
- **Verification:** `flutter analyze lib test` shows no `error •`/`warning •` outside `test/generated_migrations/`. `flutter test test/unit test/widget` ends `All tests passed!`.
- **Known pre-existing flake:** `test/unit/hub/season_service_exclusive_test.dart` "two advances in one frame" — about one run in three under load, passes alone. Not yours.

- [ ] **Step 3: Write the model**

Create `lib/domain/services/press/public_mood.dart`:

```dart
/// One result as the public reads it: who was ranked where, and how it went.
typedef MoodResult = ({
  int nationRank,
  int opponentRank,
  bool won,
  bool drew,
});

/// What the country thinks of the manager, 0–100, neutral at 50.
///
/// Deliberately NOT a second copy of the board's form term. The board already
/// weighs recent results heavily, and a mood derived the same way would just
/// double-weight them and make the gauge twice as jumpy for no new
/// information. This measures what the board does not see: EXPECTATION against
/// REALITY. Beating a side far above you thrills people out of all proportion
/// to the point it earns; grinding past a minnow moves nobody; losing to one is
/// a catastrophe the table would call a minor setback.
abstract final class PublicMood {
  /// Where a public with no opinion sits.
  static const int neutral = 50;

  /// How many recent results the public remembers. Shorter than the board's
  /// window on purpose — this is a mob, not a committee.
  static const int window = 6;

  /// The public's verdict on [recent] (newest first).
  static int of(Iterable<MoodResult> recent) {
    final games = recent.take(window).toList();
    if (games.isEmpty) return neutral;
    var score = 0.0;
    var weightSum = 0.0;
    for (var i = 0; i < games.length; i++) {
      final g = games[i];
      // The newest result weighs most: a great day wipes out a bad month.
      final weight = (window - i).toDouble();
      score += _verdict(g) * weight;
      weightSum += weight;
    }
    final avg = score / weightSum; // −1 … +1
    return (neutral + avg * 50).round().clamp(0, 100);
  }

  /// One result on a −1 … +1 scale, judged against the ranking gap.
  static double _verdict(MoodResult g) {
    // How much better the opponent was, −1 (far worse) … +1 (far better).
    final gap = ((g.opponentRank - g.nationRank) / 60.0).clamp(-1.0, 1.0);
    // `gap` is positive when the OPPONENT is ranked worse (higher number), so
    // flip it: `edge` is how much the public expected to win by.
    final expected = -gap;
    if (g.won) {
      // Beating a better side is everything; beating a worse one is the job.
      return (0.15 - expected * 0.95).clamp(-0.1, 1.0);
    }
    if (g.drew) {
      return (-0.25 - expected * 0.7).clamp(-1.0, 0.7);
    }
    // A defeat: forgiven against a giant, unforgivable against a minnow.
    return (-0.55 - expected * 0.6).clamp(-1.0, 0.15);
  }

  /// What the public's mood does to the board.
  ///
  /// Sized like the ranking bonus — the board reading the room, not being
  /// governed by it. ZERO at [neutral], so a board with no public opinion to
  /// weigh behaves exactly as it did before this existed.
  static int boardShift(int publicMood) =>
      ((publicMood - neutral) / 10).round().clamp(-5, 5);
}
```

- [ ] **Step 3: Write the generator**

Create `lib/domain/services/press/y_feed.dart` with the types from the
Interfaces block above and this behaviour:

- `forMatch` classifies the result first. This is the part with the judgement
  in it, so it is written out:

```dart
  /// How the country reads a result, before anyone opens their mouth.
  static YTemplate classify(YMatch m) {
    final gap = m.opponentRank - m.nationRank; // + = we were favourites
    if (m.scored > m.conceded) {
      if (gap <= -25) return YTemplate.winUpset;   // they were far better
      if (gap >= 25) return YTemplate.winRoutine;  // we were far better
      return YTemplate.winTight;
    }
    if (m.scored == m.conceded) return YTemplate.drew;
    if (m.conceded - m.scored >= 3 || gap >= 25) return YTemplate.lostBadly;
    return YTemplate.lost;
  }
```
- It then chooses **how many** posts to make: one for a routine result, up to
  three for a triumph or a disaster. A bigger occasion is louder.
- Voices follow the template: `stats` always posts; `pundit` and `fan` post on
  anything notable; `rival` posts only when the nation lost.
- Every post's `variant` is `varietySeed('$key|$voice') % variantCount`, so the
  wording is stable for that event and that voice, and two voices on the same
  event do not pick the same phrasing by accident.
- `punditHandle` picks from a fixed list of invented pundit names using
  `varietySeed(nation) ^ seed`, so the same country keeps the same critic.
- `args` always carries what the template needs: the opponent's name first,
  then the score as `'2–1'` for match templates; for `forEvent`, whatever the
  caller passed.

Keep `variantCount` at **4**. Each additional variant is two more translated
strings per template, and four is enough that a save does not repeat itself
quickly.

## Notes for the implementer

- **The board guard is the load-bearing test.** `publicMood: 50` must return
  exactly the old number. If it does not, the board has been re-tuned by
  accident and every existing satisfaction test is now measuring something
  else.
- **Event sources are deliberately limited to matches in this build.** The spec
  lists draws, hosts, records, retirements, ranking moves and the academy
  intake as well. `YFeed.forEvent` exists precisely so those are a template and
  a caller each, but wiring them all at once means writing a hundred translated
  strings before anything is playable. Matches are the richest source and the
  one that fires most often; the rest follow.
- **Do not let `yPostBody` have a fallback branch.** A `_ => ''` default turns
  a missing string into an invisible bug: the post renders as an empty row and
  nobody notices for a year. Exhaustive switch, and the widget test walks every
  combination.
