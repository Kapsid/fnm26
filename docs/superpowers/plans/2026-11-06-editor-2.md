# Database Editor 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The 1.1.0 editor grows deeper player control (raw qualities, fixed traits, editable day-one pools, clubs from anywhere), lets a database add clubs, sponsors and Y accounts, and gives names per-language values edited under an editor-only language picker. The Nations section goes; existing nation renames keep applying.

**Architecture:** Everything new lives in the pack JSON. `.fnmdb` / `WorldPack` format 2 adds `pools`, `addedClubs`, `addedSponsors`, `addedYAccounts`, `localized` and a per-player `traits`. `WorldPack.migrate` lifts v1 to v2 by adding empty parts, so every v1 reader (stored packs, career copies, imports, career bundles) sees "nothing new". The new parts reach a career through the 1.1.0 seams:
- `DriftPlayerRepository` (`_seededRowsFor`, `_withClub`, `_CareerWorld`) for pools, traits and added clubs;
- `ClubService.clubForSeed` for added clubs;
- `sponsorRoundOf` for added sponsors, read from the career's own world because sponsors move money;
- a zone scope for added Y accounts;
- `ActiveWorld.inLanguage` for per-language names.

An empty part changes nothing, so default careers and 1.1.0 careers read exactly as before.

**Tech Stack:** Flutter, Riverpod 2.6.1 (no codegen), Drift (no schema change), freezed (`Player` gains one field), go_router, gen_l10n through `copy/strings.csv`.

**Spec:** `docs/superpowers/specs/2026-11-06-editor-2-design.md`. Its "Decisions after the builder check" section overrides the earlier item text. The 1.1.0 spec `docs/superpowers/specs/2026-11-04-database-editor-design.md` and plan `docs/superpowers/plans/2026-11-05-database-editor.md` still hold where this plan is silent.

- **Picked traits.** Fixed traits use the game's `PlayerTrait` values only, at most `PlayerTraits.maxTraits` (2), with today's effect sizes. Nothing new is added to the match engine.
- **Fixed pools.** An untouched pool is generated per career exactly as in 1.1.0 (stored fringe rows, drawn names). It is never rebuilt from an edited squad.
- **Tablet sweeps.** Any route change is mirrored in `tabletReadyPaths` (`lib/features/shell/tablet_shell.dart`) and the sweep tests (`test/widget/tablet_full_screen_sweep_test.dart`, `tablet_route_sweep_test.dart`).

## Review Focus

1. **A 1.1.0 career or a default career, after this ships.** Same seed, same squads, names, clubs, traits, sponsor rounds and Y account names as before. Pinned in Task 1 and re-run in Tasks 3 to 8.
2. **A hostile or broken format-2 file.** Each of these is refused as `badData` and nothing is written:
   - a pool of 5 000 players;
   - a pool holding a core id or another nation's fringe id;
   - an added id outside the reserved range;
   - a `localized` entry for language `xx` or for a path nobody has;
   - an added Y account named like a game account.

   Tests in Task 2.
3. **Renaming or deleting an added club that pack players are at.** Renaming moves his players with it. Deleting puts them back to Auto (the game places them), with no dangling club names. Test in Task 12.
4. **A database whose old nation rename now breaks a rule**, for example a code that clashes with a nation a later update adds. The editor no longer has a Nations section, so the pack home must list the issue with a working Remove fix. Test in Task 9.
5. **Undo across the edit that fixes a pool.** Deleting a player from an untouched pool fixes it. Undo must give back the untouched (generated) pool, not a fixed copy of it. Test in Task 11.

### Task 2: Rules, compatibility and caps for format 2

**Files:**
- Modify: `lib/domain/services/world_pack/pack_rules.dart`, `pack_keys.dart`, `pack_codec.dart`, `lib/features/career/career_transfer_providers.dart` (bundle import runs the same checks)
- Test: `test/unit/world_pack/pack_rules_test.dart`, `pack_compat_test.dart`, `pack_codec_test.dart` (extend); `test/unit/world_pack/pack_id_space_test.dart` (new)

**Interfaces:**
- Consumes: Task 1's model and `PackPaths`; `supportedLanguageCodes` (`lib/core/config/ui_language.dart`).
- Produces in `PackRules`:
  - Constants: `poolMax = 150`, `addedClubsMax = 500`, `addedSponsorsMax = 50`, `addedYMax = 100`, `descriptionMax = 120`, `localizedMax = 20000`.
  - `static List<PackIssue> poolIssues(int nationId, List<PackPlayer> pool)`: field checks as in `squadIssues`, with no size minimum. Paths are `'pools.$n.$id.<field>'`, and a pool over `poolMax` gives `SquadTooSmall(n, have, poolMax)`.
  - `issues()` adds the following checks:
    - **Player ids:** a player id that appears twice anywhere in squads plus pools is `BadField('pools.$n.$id', duplicate)`.
    - **Pool ids:** a pool id must be `>= PoolGenerator.firstFringeId` (either a fringe id or `>= kPackPlayerIdBase`); a lower one is `BadField(.., outOfRange)`.
    - **Added items:**
      - Added ids must fall in the reserved range and be unique across all added kinds.
      - Names use `checkName`; added Y account names use `max: handleMax`.
      - An added club named like another club of the same country is `duplicate`, compared after renames and trimmed case-insensitively.
      - Added Y account names join `_yClashes`: a name equal to a game account, a rename or another added account is `duplicate`.
      - A sponsor `description` is at most `descriptionMax`.
    - **`localized` entries:**
      - The path must parse to a known root.
      - The language must be in `supportedLanguageCodes`.
      - The value must pass `checkName` with the root's max: `handleMax` for Y, `descriptionMax` for descriptions, `nameMax` otherwise.
      - An `addedX.<id>` path must name an existing added item.
  - `compatibility()` gains `required Set<String> countryCodes` and `required Map<int, ({int first, int last})> fringeRanges`, and adds an `UnknownId` for:
    - a pool keyed by an unknown nation;
    - a pool fringe id outside its own nation's range;
    - an added club in an unknown country;
    - an added Y account bound to an unknown nation;
    - a sponsor `industry` that is not a `SponsorBrand.name`;
    - a `localized` path whose key the game no longer has, checked with the same sets as the plain maps.
- `PackGameKeys.of(nationIds, {required Map<int,String> codes, required Map<int, ({int first,int last})> fringeRanges})`. Its callers read the ranges once with `select min(id), max(id) from players where id >= firstFringeId group by nation_id`.
- `PackCodec`:
  - `maxPlayersPerNation` stays the squad cap; pools are capped at `PackRules.poolMax`.
  - `fieldsOk` covers the new parts.
  - Writing always produces format 2.
